# 훅 성능 기준선

훅은 모든 `Write`·`Edit`마다 실행된다. 규칙을 늘리기 전에 현재 비용을 측정하고, 이후 같은
조건으로 다시 재어 회귀 여부를 비교한다.

이 문서의 수치는 **합성 fixture와 메모리에서 생성한 합성 소스 기준**이다. 실제 코드베이스의
성능을 나타내지 않으며 실제 코드나 개인정보를 사용하지 않았다. (D-07, D-08)

## 재현 방법

```bash
python3 tests/benchmark_hooks.py
python3 tests/benchmark_hooks.py --json
```

`tests/benchmark_hooks.py`는 합격/불합격 harness가 아니다. 하드웨어·운영체제·Python 버전에
따라 달라지는 시간을 CI의 고정 임계값으로 사용하지 않는다. 대신 입력, 준비 실행 횟수, 표본 수,
측정 환경을 출력해 같은 조건에서 비교할 수 있게 한다.

측정 계층은 둘이다.

1. **새 프로세스 훅 전체** — 매 표본마다 Python 하위 프로세스를 새로 실행한다. 인터프리터
   시작, 모듈 import, stdin JSON 처리, 설정·사전 로드, 판정, stdout 직렬화를 포함한다.
2. **동일 프로세스 엔진 내부** — 엔진을 한 번 import한 뒤 설정 탐색, 사전 로드,
   `analyze()`를 각각 측정한다. 어느 단계가 입력 크기에 따라 늘어나는지 구분하기 위한 값이다.

각 시나리오는 준비 실행 5회 뒤 50회 측정한다. p95는 오름차순 표본의 nearest-rank 방식이다.
합성 대형 소스는 개인정보 별칭이나 암호화 호출이 없는 단순 메서드를 한 줄씩 생성한다.

## 해석과 다음 규칙의 제약

작은 fixture에서는 판정 자체가 1ms 미만이고 훅 전체가 약 30ms다. 설정 탐색과 사전 로드도
각각 0.1ms 미만이다. 따라서 작은 파일의 대부분은 새 Python 프로세스 시작과 모듈 import 등
고정비로 보인다. 이는 단계별 값을 비교한 **추론**이며 고정비만 별도로 직접 측정한 값은 아니다.

2,000줄 합성 입력에서는 Java `analyze()` 중앙값이 112.195ms, Kotlin이 95.331ms다. 훅 전체와의
차이도 작은 입력의 약 30ms 고정비와 비슷하다. 대형 파일에서는 `analyze()`가 주된 비용이다.

현재 수치만으로 Phase 2를 중단할 이유는 없다. 다만 적법한 `Edit`는 PreToolUse와 PostToolUse가
각각 파일 전체를 판정하므로 대형 Java 입력에서 두 훅이 각각 142.101ms, 143.929ms였다. 새 규칙은
파일 전체 정규식 순회를 무제한으로 추가하지 않고 기존 `prepare()` 결과와 얕은 전파 결과를
재사용해야 한다. `K-ENC-001` 구현 뒤 같은 명령을 다시 실행해 특히 다음 값을 비교한다.

- 작은 Java PreToolUse 전체와 `analyze()` p95
- 2,000줄 Java PreToolUse·PostToolUse 전체 p95
- 2,000줄 Java·Kotlin `analyze()` p95

실제 코드베이스에서 측정하더라도 결과는 공개하거나 이 문서에 옮기지 않는다. (D-07)

재측정했다. 각 시나리오 준비 5회·측정 50회이며 기본 대형 Java·Kotlin과 추가 대형 Java는 모두
2,000줄이다. 기존 39개 측정은 그대로 두고 비밀번호 필드·암호 보조 메서드 입력의 PreToolUse와
analyze 4개를 추가해 총 43개를 비교했다. 입력 생성은 `tests/benchmark_release.py`에 있다.

```bash
python3 tests/benchmark_release.py --root /path/to/snapshot --samples 50 --warmups 5
```

기준 공개 커밋은 `eae6558`이며 후보 엔진 SHA-256은
`519fc0fa0e406b0fbd4f28554d5bbedb54c7bf1cd2574a254432fa0b02815f6f`이다.

개선율은 특정 합성 입력 기준이고 모든 입력의 시간·호스트 체감을 보증하지 않는다.

해소됐다. 작은 훅의 위 절대 증가도 공개한 상태에서 새 패치 배포 조건을 충족한다고 판단했다.
